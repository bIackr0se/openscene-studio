# OpenScene build loop

## Contract

- Goal: let a trainer adapt one trusted video to a learner need without rebuilding the lesson or giving the agent control over approved answer content.
- Verifier: a cold viewer can explain the human problem, ChatGPT's page-owned edit, the learner's action, and the trainer's final decision after one complete interaction.
- Exit: the local build, hosted site, public source, demo film, and Devpost copy show the same Studio product and revisioned WebMCP contract.
- Keep policy: retain a change only when it improves the runnable adaptation loop, its evidence, or the viewer's understanding.

## Frozen product path

1. The open video project starts with one source scene and two authored practice paths.
2. A trainer tells ChatGPT that a learner cannot use stairs and does not know the German phrase.
3. ChatGPT inspects the live project through WebMCP.
4. ChatGPT proposes a step-free draft using the page-approved lift response pack.
5. The Studio links the human need, learner line, pause, filmed answer, board, and revision in one visible branch.
6. The trainer rehearses the draft. The video stops at the learner's turn.
7. A mismatched line keeps the answer locked. The matching line releases the filmed response and answer board.
8. The trainer keeps the cut or restores the earlier project.

## Product rules

- Keep the footage, scene graph, and selected branch recognizable in the first viewport.
- Show the source cue, human turn, and response cue on one timeline.
- Show a WebMCP proposal as a draft until a person keeps it.
- Let the agent select only a page-approved response pack. The pack owns the factual answer, board, filmed take, and answer cue.
- Keep the learner's phrase selection and `Keep path` as human-controlled Studio actions.
- Label local samples as `NO AGENT CALL`.
- Keep the clips silent. Use a separate narrator only in the submission film.
- Do not imply live travel guidance, speech recognition, character perception, continuous generated motion, or a measured accessibility outcome.

## Visual rules

- Use the director's-bench composition: full stage, one scene sheet, one timeline, one causal slate.
- Use signal yellow for the active edit and route mint for a verified page-owned state.
- Use SF Pro or Segoe UI across reading copy, labels, timecodes, and tool evidence. Distinguish utility text with weight, restrained spacing, color, and tabular numerals, not a separate code-like typeface.
- Keep reading copy at 12 pixels or larger and essential utility text at 10 pixels or larger.
- Use square editorial controls. Avoid card mosaics, glass panels, decorative gradients, and ambient motion.
- Use clean cuts or a short directional slide between full-page, dual-capture, and code views. Never crossfade two readable text surfaces.
- Let the learner click and response onset carry their own quiet beat.

## Verification order

1. Run the Studio state and WebMCP tests, including failure probes for injected response content and stale revisions.
2. Run the Studio browser paths for proposal, edit, preview pause, wrong and correct lines, keep, undo, responsive layout, reduced motion, and accessibility.
3. Type-check, lint, format, and build.
4. Prove the media verifier accepts the intended four clips and rejects missing media, exposure-only motion, wrong endpoints, and scene replacement.
5. Verify the active release manifest names the six Studio tools and exact frozen media.
6. Run the premium UI audit, design lint, resolver checks, and a cold-reader pass on the rendered Studio.
7. After release authorization, test the hosted page without the owner's session and record a real ChatGPT WebMCP invocation.
8. Freeze the final links, screenshots, captions, public source archive, and under-three-minute film before entering Devpost.

## Current boundary

The private candidate contains the accessibility-first Studio, six revisioned page tools, three page-approved response packs, a human-gated learner turn, silent response media, explicit keep and undo actions, and a deterministic test boundary.

The release still requires external actions: public hosting, native ChatGPT proof against that hosted build, public source, the final narrated film, and Devpost completion. Each remains an explicit human gate.
